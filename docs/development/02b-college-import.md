## 现有代码审查与最小扩展

原 `import_workbook()` 只接受五张规范化工作表，不能识别本轮单工作表“学生×课程”的学院导出。可以复用XLSX类型/大小/压缩包/外链安全检查、`Dataset.validate()`、五张关系型表、`Database.replace()`事务、`AnalyticsEngine`和三种展示投影。现有Agent及四个工具不变。

真实格式还暴露了演示契约限制：入学年不是1–3年级值、课程名含中文与罗马数字、实际存在0.25/0.75/1.25/2.5学分。只增加解析器而不扩展契约会失败或截断学分。因此小范围扩展模型与SQL约束，并只调整统计核心的加权部分使用精确Decimal；普通均分、及格/不及格率、优良率和分层公式保持原逻辑，不另写统计引擎。

物理布局由`PRAGMA user_version=2`记录，旧库的两个维度表在受控事务中迁移并核查外键；旧记录内容指纹保持不变，新增元数据为空时不进入旧载荷。默认启动不会重置已有数据。迁移是升级操作，不能以旧程序继续写新布局。

## 实际支持的输入

- 一个可见成绩工作表，前25行中含单行字段表头，可有表头之前的合并标题；字段/数据区域合并会阻止提交。通过字段内容发现位置，允许列重排、标题行数变化，不按文件名推断学生归属。
- 必需字段：学号或学生学号，班级或行政班级；姓名字段不进入分析数据库。可核对独立的年级、专业字段，冲突行列入排除。
- 课程表头示例（合成）：`Web技术基础，专业必修课，必修，学分2，学时32，2025-2026-1`。支持中文/英文逗号、分号、换行分隔，以及`2025-2026学年第一学期`形式。第一版要求名称、类别、性质、学分、学时、学年学期齐全；不猜缺失学分和学期。
- 识别课程门数、不及格门数、平均分、总分、所得学分、绩点、排名等已声明汇总字段并忽略其值；未知字段按列坐标警告，不作为成绩猜测。
- 班级如`24软工2班`、`2024级软件工程2班`、`25计科1班`、`23网工1班`；别名字典支持软件工程/软工、计算机科学与技术/计科、网络工程/网工。入学年支持1900–2199，2位年份按2000年代展开。未知专业保留班级原标签、标为`unspecified`并警告，不丢弃学生或猜成软工。新专业需一起扩展别名字典与标准枚举。
- 课程学期`2025-2026-1/2`映射为`2025-T1/T2`，起始年代表学年，并保留原`academic_year`。现有Term契约支持2000–2099学年。
- `.xlsx`最多5 MiB、展开32 MiB、256列、5000名学生、50000条选课成绩；同时限制实际XML坐标，不能靠错误的工作表dimension绕过。拒绝多表、外链、嵌入对象、加密、宏及不支持格式。原五表导入API保留。

显示名称只移除明确元数据并规范空白，不无差别删除数字、英文字母或罗马数字。`Web`、`工程实践2`、`体育 III`、`高等数学 (I)-1`有专门测试。保存原课程表头、源签名、类别、修读性质、学分、学时、学年、学期和可选课程代码。

源签名由名称、类别、性质、学分、学时、学期、代码等完整属性生成；同名异属性课程分别保留并提醒。内部导入课程ID为`I`加24位摘要，同源课程按入学年保守拆分，以复用既有年级关系校验；不会以课程名称直接合并。完整签名相同的重复列会阻止提交，需先核对原表。

## 空值、异常与重复规则

1. 有效学生中整列全空且无状态：本次排除该课程，不创建课程/选课成绩；确认事务保留已有课程目录，不因空列删除历史目录。
2. 部分空白：仅有明确成绩或可识别状态的单元格生成记录。空白不推断缺考、免修、不及格或未选课。
3. 0分是真实有效成绩。数值限0–100、最多2位小数；不把未知文本或成绩注释猜成数字。
4. “缺考”映射`missing`，“免修”映射`exempt`，均无数值；缓考、优秀/良好等其他状态或公式不自动折算，排除该单元格并提示坐标。全列均异常时另标“无可导入成绩或状态”。
5. 原学号只在解析内存中用于去重和建立关系，最终使用本批次内部ID及`Imported Student NNNN`别名；原姓名被忽略。别名不能用于跨批次人员追踪。
6. 重复学号且班级/课程单元格相同：整行去重并提醒。存在冲突：默认`block`，不签发可提交Token；操作者可对照原表后明确选`first`或`last`，保留整行并计数排除的重复行及非空成绩单元格。**不自动合并互补成绩，也不判断哪一行具有教务效力。**
7. 无法识别的学生标识/班级、与独立年级/专业冲突的行会排除并列出坐标。问题明细最多200条，分类计数包含全部问题；不回显未知单元格原值。

覆盖率与统计仅描述成功解析的记录，不能解释成全部学生本应修读课程的通过率。有效学生计数表示身份/班级可解析，不保证每名学生都有可导入成绩。原表的绩点、排名、课程门数与学分汇总均不用于反推成绩。

## 预览与提交调用链

```text
Streamlit file_uploader
→ DashboardClient.college_preview（multipart HTTP）
→ POST /api/datasets/college/preview
→ CollegeImportService.preview
→ XLSX安全检查 + XML坐标预检 + parse_college_workbook
→ 单行表头识别、班级映射、课程签名、宽表转长表
→ Dataset.validate() → 脱敏预览、排除清单、15分钟签名凭据
→ 操作者核对并勾选，再点击确认
→ POST /api/datasets/college/commit（同文件 + Token + confirmed=true）
→ 验签、过期/文件校验、重解析及规范化版本校验
→ Database.replace(expected_version=..., preserve_courses=True, source="uploaded_local_only")
→ 一个写事务中核对预览时的数据版本、保留课程目录、检查冲突、写五表并更新数据版本
→ 清除旧报告/AI响应和上传控件状态 → 重新读取目录 → AnalyticsEngine.course_report
→ 原Table A、Figure B、Table C、CSV展示
```

上传和预览不修改数据库；勾选也不提交。预览凭据绑定文件SHA、重复策略、规范化结果和原数据版本；文件、策略变化会要求重新确认。后端重启或15分钟过期需重预览。当前库被其他请求修改会返回409，旧预览不能覆盖新数据。

确认导入是替换当前学生及选课成绩，**不是追加多个学期的历史成绩**。课程目录保留，已有同ID但定义不同会拒绝并回滚。新版本是整个激活数据集的内容指纹，同一内容再次导入可能保持相同版本，不应把版本当作递增批次号。

FastAPI可能对较大上传临时spool，接口始终关闭上传对象；应用不主动持久化原工作簿。原始文件不进Git，`.xlsx/.xls`已加入忽略规则，测试在内存生成合成工作簿。错误/日志/回执不包含真实姓名、原学号、逐人预览或个人成绩。当前来源仍为`uploaded_local_only`，现有Agent会在模型调用前拒绝访问；没有新增个人名单查询接口。

## 实际参考文件的本地聚合校验

真实参考表在本地读取，仅输出汇总；**运行中的应用数据库未被覆盖**。默认存在5组冲突学号，系统正确阻止提交。参考表另有2行无法识别学生标识，按异常行排除；包含未登记专业，保留原班级归属及警告，未强行映射。

| 聚合项目 | 结果 |
|---|---:|
| 工作表 / 表头行 / 课程列 | 1 / 第3行 / 69 |
| 排除的全空课程列 | 1 |
| 学生行 / 无效学生行 / 重复行 | 177 / 2 / 5 |
| 默认策略 | `block`，不能提交 |
| 显式保留第一行 | 170名学生、8班、72个按入学年区分的课程、2447条成绩 |
| 显式保留最后一行 | 170名学生、6班、70个按入学年区分的课程、2483条成绩 |
| 两种策略的课程学期 | `2025-T1` |

两种显式策略均只在临时隔离数据库中完成技术验证，不代表工作人员已经选择了正确教务行。验证起点为4名合成学生、2班、3门课程、6条成绩；保留原3门课程后，第一行策略得到75门目录课程及2447条成绩，最后一行策略得到73门目录课程及2483条成绩。均可通过既有统计及三视图投影；上传来源的`external_llm_allowed=false`。临时数据库随后清理，记录只保留条数，不含个人信息。

不要把2447或2483直接当作唯一正确业务结果：5组冲突需由工作人员查原始导出与教务规则后决定；页面保留这一决策，不替人猜测。

学习片段一：`parse_score()`返回`None`表示“不生成记录”，返回`("missing", None)`表示“存在明确缺考状态”。两者都没有数值，却是不同业务事实；0则返回`("graded", 0)`，不能用真假值判断其有效性。

学习片段二：Adapter输出已有`Dataset`并调用`validate()`，随后复用同一个事务仓储；SQL仍来自固定代码，外部文件不能生成SQL。解析、验证、写入、统计有清楚边界，各层不用复制下一层的业务公式。

学习片段三：预览Token只证明“同一文件、同一解析策略和原版本”，写入时的`expected_version`还必须在数据库写事务内检查。仅在前端比较版本存在竞争窗口。保留目录与替换成绩也在这一个事务完成，失败就回滚。
